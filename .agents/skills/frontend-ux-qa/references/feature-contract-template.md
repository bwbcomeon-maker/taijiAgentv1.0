# 功能契约

按已确认的产品功能契约和授权角色检查受影响路径。内部 API、明确 CLI-only 的能力、授权角色之外的操作，不因缺少普通用户 UI 自动判为缺陷；既有产品回归不得借“本轮范围外”排除。已经承诺通过 UI 提供的能力，不能在审查时临时改称内部功能来豁免。

| 能力及产品契约依据 | 目标角色 / UI、CLI 或内部入口 | 数据/API/状态存在 | UI 入口存在 | 用户反馈存在 | 错误处理存在 | 空/加载/禁用状态 | 键盘/可访问性支持 | E2E/浏览器测试 | 状态 | 备注 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---|---|

规则：

- 功能契约承诺通过 UI 提供的能力必须对相应授权角色有可见、可发现、可访问的入口。
- 受影响的 UI CRUD 功能必须端到端检查。
- 如果功能契约承诺某个 UI action，但相应授权角色的 UI 不暴露，状态为“失败”，至少标记为 P1；主流程阻塞为 P0。
- 如果承诺的 UI 入口只存在于隐藏快捷键、未文档化手势、URL hack 或开发者工具中，状态为“失败”。
- 如果检查没有运行，状态为“未验证”。
- 如果存在 P0/P1，则前端任务不能标记为完成。

不适用的 UI 检查填写“不适用”并说明契约或角色依据；适用但未执行的检查仍填写“未验证”。
