# 太极 Agent 销售就绪门禁

本文定义太极 Agent 对外销售或客户现场交付前的证据边界。没有当前源码、当前制品和真实目标机绑定的实时证据时，不得把历史记录、macOS 检查、模拟测试或某个旧 DEB 表述为“可销售”或“目标机已验证”。

完整操作步骤以 [`runbooks/taiji-kylin-uos-offline-delivery.md`](./runbooks/taiji-kylin-uos-offline-delivery.md) 为准；本文只维护销售合同和放行口径，避免复制脚本字段后发生漂移。

## 当前阶段与支持边界

当前只实施第一阶段：国产 x86 Linux 单一 DEB。Windows 安装包必须在第一阶段的真实麒麟或统信目标机验收通过后，作为第二个独立阶段启动，不能与 Linux 同时放行。

第一阶段候选范围：

- x86_64/amd64；
- Debian-like 的 Kylin、UOS、openKylin 类系统；
- 具备图形桌面、`dpkg`、`apt`、`systemctl`、普通登录用户和受控管理员授权；
- 每个制品遵循源码受控的 `packaging/linux/compatibility-policy.json`，代表环境由认证矩阵验证；
- 系统能力必须满足 policy 下限，产品包不捆绑或替换 glibc。

当前不承诺 RPM-only、ARM/aarch64、无图形桌面或现场策略禁止 Electron/loopback/桌面安装器的终端。支持矩阵或 policy 变化时，重新构建、重新演练并重新跑六正六负认证矩阵；不要求每台终端采集基线。

## 四类制品不能混用

制包输入、内部工作区、内部证据和客户安装目录是四个不同合同：

1. **制包输入三件套**是同一冻结提交生成的 `tar.gz`、`manifest.json` 和 `tar.gz.sha256`，只交给受控制包机。
2. **内部构建验收工作区**包含候选、工具链、临时源码、日志和工作中证据，不是客户目录，也不是最终不可变档案。
3. **内部完整证据档案**保存构建、断网生命周期、目标验收、CI、签名、release-check 和发布回执；发布前先冻结门禁输入，发布器成功后才用回执最终闭合。
4. **客户安装目录**由 `packaging/linux/deb/publish-single-deb.sh` 在所有门禁通过后生成，必须且只能包含 `taiji-agent_${VERSION}_amd64.deb` 一个与内部候选逐字节、SHA256 一致的 DEB。客户终端不下载依赖、不执行源码构建，也不需要第二个安装文件。

当前 v3 Docker/VM 演练直接消费自包含候选 DEB 和受控证据，不要求历史 `离线依赖/Packages` 或 `Packages.gz` 本地 APT 仓库。历史 v2 仓库只能用于旧包诊断，不能进入当前发布路径。容器演练也不能替代真实目标机双击安装。

## 六级证据标签

| 标签 | 最低证据 | 明确边界 |
| --- | --- | --- |
| 制包输入已准备 | 正式 `main` 当前冻结 commit 的输入三件套、逐件 basename/字节数/SHA256 和源码预检通过 | 不代表生成了 Linux DEB |
| 候选 DEB 已构建 | Linux amd64 制包机依据 canonical policy 以 strict lock 生成候选和内部证据，正式 `00` 及其最终产物模式 `01` 通过 | 不代表离线安装成功 |
| 离线安装已演练 | 干净 Linux amd64 容器、VM 或 chroot 在断网状态下只使用内部本地制品完成安装、诊断、卸载和重装，并生成当前产物绑定证据 | 不代表麒麟/UOS 桌面已通过 |
| 目标机已验证 | 真实 Kylin/UOS/openKylin x86_64 图形终端完成单 DEB 双击安装、首次配置、安装态 Electron、CLI、真实模型与附件、关窗退出和诊断导出，证据经发布负责人复核并签名 | 只适用于认证矩阵绑定的代表类别和 DEB 摘要 |
| 发布前证据门禁已闭合 | 生命周期、目标、CI v2、认证与 publication 两份签名和 release-check 全部绑定同一身份并被冻结 | 发布器尚未运行，内部档案还没有最终发布回执 |
| 客户单 DEB 已发布 | 发布器原子生成恰好一个 DEB 的客户目录，并用发布回执最终闭合内部证据档案 | 只证明该签名候选已按本合同发布 |

六级证据必须按顺序形成，不能互相替代。文件存在、测试数量、旧日志、旧截图或手写布尔值都不能升级证据标签。

## 目标机双击与离线证据

目标机安装验收必须使用 `验收工具/observe-single-deb-install.py`：观察器在安装前启动，并在同一进程、同一机器和同一启动周期内记录以下事实：

- 安装前 `taiji-agent` 没有 dpkg 记录；
- 客户候选目录从开始到结束都只有一个与 manifest 同名同 hash 的 DEB；
- 太极用户配置、数据、状态和桌面 user-data 在首次启动前不存在；
- 安装过程中持续采样未发现 UP 的非回环接口、全局地址或非回环路由；
- dpkg 状态由未安装变化为 `install ok installed`。

操作系统无法可靠区分鼠标双击与其它等价启动方式，因此证据必须如实拆分：机器观察记录证明安装前后、制品和断网事实；现场操作员使用严格确认语句出具“通过文件管理器双击并由系统图形安装器完成”的人工见证，并附系统图形安装器截图。人工见证不能被表述为机器自动识别，必须由发布负责人复核后随顶层目标证据一起签名。

首次启动后必须完成授权、模型、工作区和安全策略检查。安装后的正式验收必须从 DEB 安装的 root-owned `/usr/bin/taiji-agent-acceptance` 启动；外部工作区只提供 manifest、安装观察、截图等数据，不能直接执行其中可变的 `04` 或验收工具作为信任根。桌面验收驱动必须从可见的首次配置工作台开始，通过真实可点击控件推进，并且只在服务端返回 `completed=true` 且 preflight 全部就绪后才继续对话验收。不得关闭、跳过或用 Web 页面结果代替安装态 Electron。

同一制包机可以做内部安装、卸载和重装诊断，但不能自动升级为“客户干净首次安装已验证”。该结论必须来自无 `taiji-agent` 包记录和太极用户状态的可信恢复点或另一台代表终端，并绑定同一个 DEB 摘要。

这套证据是受控交付流程中的软件采样、现场人工见证和发布审批证据，不是 TPM 或远程证明级别的防恶意管理员证明。控制目标机 root 的人能修改系统标识、进程和证据文件；因此签名只证明发布负责人对所收证据的完整性和批准，不得表述为可对抗恶意 root 的机器不可伪造证明。

## 放行链

Linux 客户单一 DEB 只能按以下顺序产生：

1. 从已复验的正式 `main` 冻结唯一 commit，生成并逐件复验输入 `tar.gz`、`manifest.json`、`tar.gz.sha256` 三件套。
2. 在兼容 Linux amd64 制包机以 `TAIJI_UV_LOCK_MODE=strict` 运行 `00_制包机_生成离线交付包.sh`；`00` 会在固定候选 DEB 后自动以产物模式执行最终 `01_制包机_发布预检.sh`，不需要也不应再用默认 source-only 模式单独重跑 `01` 充当候选证据。
3. 在断网的干净 Linux amd64 环境完成 fresh install、remove、purge、reinstall 和受控旧版本升级/失败回滚演练，生成结构化证据；正式旧版本入口必须验证真实 detached signature，不能在容器内伪造占位签名。
4. 在六个正向代表环境和六个负向边界上使用同一 DEB SHA 形成认证记录；安装后的执行代码来自 `/usr/bin/taiji-agent-acceptance`。
5. 为冻结 commit 采集可信 GitHub CI v2 三件套，并在正式签名/发布前按源码合同实时复验。
6. 使用用途、有效期、source commit 和 DEB 身份明确的独立 certification/publication challenge，先生成并签名 `certification-set.json`，再生成并签名 v3 release evidence；不能在最终门禁阶段换 nonce 或跨用途复用。
7. 执行 `scripts/taiji-release-check.sh`，冻结发布前证据门禁；任何实物变化都必须重新组装和签名。
8. 执行 `packaging/linux/deb/publish-single-deb.sh`，生成只含一个固定 basename DEB 的全新客户目录，并以固定 allowlist 的内部 receipt 最终闭合证据档案。

发布私钥不得复制到目标终端、安装包、客户目录或源码仓库。客户目录已存在时发布器拒绝覆盖；门禁或回执生成失败时不得留下看似成功的正式回执。

## 销售口径

只有六级证据全部绑定同一正式 `main`、产品版本、DEB hash 和统一 policy/认证集后，才能说：

- 当前单一 DEB 已在明确的 Kylin/UOS/openKylin x86_64 代表环境矩阵上完成离线双击安装和真实桌面验收；
- 客户在该统一兼容范围内只需双击一个 DEB，不需要联网下载或额外安装文件。

在此之前必须按实际状态说“分支候选”“制包输入已准备”“候选 DEB 已构建”“离线安装已演练”“目标机已验证”或“发布前证据门禁已闭合”，不能提前说“销售级安装包已完成”。Linux 目标机证据未闭合前，也不能声称 Windows 安装包阶段已开始或已支持 Windows。
