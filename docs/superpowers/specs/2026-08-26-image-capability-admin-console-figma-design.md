# 图片能力中心管理员控制台 Figma 设计

## 目标

重设计“设置 → 模型配置”中的图片能力中心，使需要管理多个 Provider、端点和独立凭据的管理员能够在一个页面快速判断图片理解与图片生成是否可用、由什么配置驱动，以及如何修复未验证或失败状态。

本设计交付完整的桌面端“模型配置”页面 Figma 稿：复原截图中的窗口、左侧导航、背景、模型配置头部、授权信息、主模型和辅助模型等上下文；只重新设计“图片能力中心”。不改变现有 Provider、凭据、验证接口或保存语义。

## 用户与验收目标

管理员在不展开复杂字段的情况下应能：

1. 看见图片理解与图片生成的独立配置与验证状态；
2. 判断每项能力当前使用的 Provider、模型、凭据引用和实际路由；
3. 从各能力卡直接进入配置或执行真实验证；
4. 在修改共享凭据前了解会影响哪些能力；
5. 在窄内容列中完成上述判断而不出现横向裁切。

## 信息架构

### 0. 页面上下文（复原，不重设计）

Figma 主画板保留截图同一套浅蓝玻璃风格：桌面窗口边框、左侧“太极智能体”导航栏和“设置”选中态、右侧背景、页面标题、授权区、主模型区与辅助模型摘要。它们用于提供完整、可评审的页面上下文，保持现有层级与视觉语言；本次不改写其交互与业务文案。

### 1. 状态与动作条

页面标题为“图片能力中心”，副标题说明其管理范围。状态摘要展示已配置、已验证、待验证和失败数量；右侧放置“全部验证”主操作与“刷新状态”次操作。

若存在待验证或失败项，显示持久的状态提示，其中包含原因、影响范围和可执行的下一步；“真实验证”附带可能产生外部调用费用的提示。

### 2. 能力总览

图片理解与图片生成使用并列能力卡，窄屏切换为单列。每张卡包含：

- 能力名称、简短使用说明和状态徽标；
- 当前 Provider 和模型；
- 凭据引用及“共享/独立”标识；
- 实际路由摘要（例如地区、端点或“当前无可用生图路由”）；
- “配置”与“立即验证”两个可发现的操作入口。

默认态只显示判断所需内容，不显示 API Key 输入、平台凭据细节或高级字段。

### 3. 配置抽屉

点击单张能力卡的“配置”后，从右侧打开抽屉，分为“接入配置”“模型与路由”“高级设置”。Provider 切换后只显示兼容字段。凭据字段只显示凭据引用、状态和用途，绝不回显密钥。

保存成功后该能力进入“已配置，待验证”；验证执行中、成功、失败均在卡片和抽屉内同步反馈。失败需说明失败阶段、具体原因和恢复入口。

### 4. 凭据库

能力卡下方的“凭据库”列出名称、Provider、健康状态与被引用的能力。修改共享凭据时，在保存前显示影响范围；管理员可以新增独立凭据而不覆盖既有引用。

## 交互与状态

| 场景 | 可见反馈 | 下一步 |
| --- | --- | --- |
| 未配置 | 灰色“未配置”状态，说明缺少 Provider 或凭据 | 配置 |
| 已配置待验证 | 琥珀色“待验证”状态，提示尚未进行真实调用 | 立即验证 |
| 验证中 | 按钮禁用且显示进度，状态区保留当前配置 | 等待或取消（如现有能力支持） |
| 验证成功 | 绿色“已验证”，显示最近验证时间 | 配置或再次验证 |
| 验证失败 | 红色“验证失败”，显示失败阶段与建议 | 修复配置或重试 |
| 修改共享凭据 | 保存前显示受影响能力 | 确认修改或新增独立凭据 |

## 可访问性与响应式要求

- 状态既有文字和图标，也有颜色；
- 所有图标按钮具有可见标签或可访问名称；
- 配置抽屉打开后焦点进入抽屉，关闭后回到触发按钮；
- 状态变化通过适当的 live region 宣告；
- 宽屏两张能力卡并列，内容列变窄时卡片单列；不得依赖整窗宽度造成裁切；
- 按钮最小点击区域和焦点状态在 Figma 稿中明确体现。

## Figma 交付与验证

Figma 文件包含一个完整的桌面端主页面和一个配置抽屉展开态。除图片能力中心外，主页面复原截图的页面框架和上下文区域。视觉验收重点是：状态层级清楚、主操作易发现、共享凭据影响可理解、长字段不挤压总览、窄屏不横向裁切，以及新模块与既有玻璃化视觉语言一致。

本次仅交付 Figma 设计稿。真实浏览器、代码实现、Provider 真实验证、自动化可访问性和视觉回归均不属于本交付，状态为未验证。
