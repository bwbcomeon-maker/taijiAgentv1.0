# 太极 Agent 全环境统一授权与鉴权设计

日期：2026-08-26
状态：已获用户批准，待实施

## 1. 目标

取消“开发环境无需授权”特例。开发、测试、生产及其他实际运行环境统一执行同一套授权与鉴权规则：授权必须有效、签名必须可信、机器绑定必须匹配、授权必须处于有效期和版本范围内，且系统时间回拨检查必须通过。任何实际运行入口都不得通过环境类型或环境变量关闭、弱化或绕过上述规则。

## 2. 已确认的现状与根因

当前无参运行时授权入口在识别到非安装态源码运行时，会直接返回 `not_required`，因此 `require_valid_license()` 不会阻止后续执行。设置页再把该状态渲染为“开发环境无需授权”和“开发源码模式无需授权，不影响本机验证”。这是一条真实的后端策略分支，不是单纯的界面文案问题。

## 3. 范围

本次包含：

- 授权核心策略与实际执行门禁；
- 源码、测试和安装运行时的授权资源解析；
- WebUI 授权状态、导入、机器码和错误反馈；
- Agent API、聊天、专家团及其他已有实际执行入口；
- 授权单元测试、WebUI 合同测试和真实浏览器回归；
- 受影响的授权说明、功能契约和 UX QA 证据。

本次不包含：

- 新增联网激活、扫码激活或授权服务器；
- 改变现有离线授权文件格式、V3 机器绑定算法或签发业务流程；
- 创建 Tag、Release、安装包、部署或目标机验收；
- 重新设计设置页面的整体布局。

## 4. 设计原则

### 4.1 策略统一，资源位置按运行载体解析

所有实际运行环境共享一份固定策略：

- `required = true`；
- `machine_binding_required = true`；
- 仅接受当前 V3 机器绑定，不自动放宽旧版绑定；
- 使用相同的产品、受众、签名身份、有效期、版本范围和时间回拨规则；
- 授权缺失、过期、未生效、签名无效、版本越界、机器不匹配、设备身份不匹配、时间异常或安全属性异常时均失败关闭。

环境差异只能用于解析受信资源的位置，不能改变策略：

- 安装态继续使用安装目录中的受信公钥和版本文件，以及当前系统账号下的授权、设备身份和状态文件；
- 源码运行使用受信源码根中的同一签发公钥身份和仓库根 `VERSION`，授权、设备身份和状态文件仍位于当前系统账号的标准产品目录；
- 两种载体必须核对同一固定公钥指纹，不能通过环境变量替换验签公钥；
- 实际运行入口不能接受关闭授权、关闭机器绑定或允许旧绑定的环境变量覆盖。

路径不同属于安装载体差异，不构成授权或鉴权特例。

### 4.2 运行时门禁与测试夹具分离

`require_valid_license()` 继续作为不接受调用方策略参数的最终运行时门禁，所有现有执行入口统一调用它。低层校验函数可以保留显式路径、时间、公钥和机器指纹参数，仅用于纯函数验证、候选授权导入和隔离自动化测试；这些参数不能被实际运行入口透传，也不能形成产品绕过开关。

自动化测试通过临时密钥、临时授权文件、临时设备身份和隔离目录构造有效、过期、篡改及不匹配场景。测试夹具不读取真实客户授权，不修改日常用户授权状态，也不允许被源码启动器或正式运行入口启用。

## 5. 组件设计

### 5.1 授权核心

- 用一个规范化的运行时授权策略替代源码 `not_required` 分支；策略名称不再表达“开发免授权”。
- 将“策略选择”与“资源解析”分开：策略恒定，资源解析器根据可信运行载体返回公钥、版本、授权、设备身份和状态文件。
- 无参状态查询、最终执行门禁和授权导入完成后的状态刷新都使用同一规范化运行时策略。
- 检测到授权策略覆盖变量时失败关闭；错误码沿用可机器识别的稳定错误结构。

### 5.2 启动与执行入口

- 源码桌面、源码 CLI、WebUI、Agent API 和安装态运行不得设置或依赖关闭授权的变量。
- 聊天、专家团和其他已有真实执行入口在创建 Agent、启动流或提交外部工作前完成授权门禁。
- 健康检查、授权状态查询、机器码导出和授权导入保持可用，使无授权用户能够完成恢复。

### 5.3 WebUI

- 删除 `not_required` 的成功态映射以及两处开发免授权文案。
- 状态只展示用户可理解的真实结果：授权有效、未安装授权、授权已到期、授权无效或授权未知。
- 未授权状态继续提供机器码、导入和刷新入口；错误反馈说明原因与下一步，不暴露本地源码路径、密钥或令牌。
- 颜色不作为唯一状态线索，保留文字、图标和可访问名称；不改变页面总体信息架构。

## 6. 数据流

1. 实际运行入口调用无参授权门禁。
2. 授权模块识别可信运行载体，只用于解析受信资源位置。
3. 统一策略固定要求授权、V3 机器绑定、固定签发身份和防回拨。
4. 校验模块读取授权、设备身份和状态，完成签名、声明、版本、时间与机器匹配校验。
5. 校验有效时允许执行，并安全更新最近成功校验状态。
6. 校验失败时返回稳定错误码和面向用户的中文信息；调用方在创建 Agent 或启动真实工作前停止。
7. 用户可通过机器码与授权导入入口恢复，导入候选也按相同策略验证，成功后原子替换当前授权文件并刷新状态。

## 7. 失败与恢复行为

| 场景 | 用户可见状态 | 执行行为 | 恢复入口 |
| --- | --- | --- | --- |
| 未安装授权 | 未安装授权 | 阻止实际执行 | 导出机器码、导入授权、刷新 |
| 授权过期或未生效 | 明确时间状态 | 阻止实际执行 | 联系服务方、导入新授权 |
| 签名、内容或安全属性无效 | 授权无效 | 失败关闭 | 重新导入或修复安装 |
| 机器或设备身份不匹配 | 授权与本机不匹配 | 阻止实际执行 | 使用当前机器码重新签发 |
| 系统时间回拨 | 系统时间异常 | 阻止实际执行 | 校准时间后刷新 |
| 试图关闭或弱化策略 | 检测到不允许的策略覆盖 | 失败关闭 | 移除覆盖并重新启动 |
| 授权有效 | 授权有效 | 允许执行 | 无需恢复 |

## 8. 测试与验收

### 8.1 RED 证据

实施前增加或修改回归测试，证明当前源码运行仍会返回 `not_required`、不会读取授权且不会阻止执行；这些测试在新预期下必须先失败。

### 8.2 自动化验证

- 授权核心：源码与安装态缺失授权均阻止执行；有效授权均放行；关闭授权和关闭机器绑定的覆盖均被拒绝；V3 机器绑定、过期、未生效、版本越界、时间回拨、篡改、错误机器和错误设备身份保持一致。
- 入口：Agent API、WebUI 聊天与专家团在创建 Agent、启动流或执行外部工作前失败关闭。
- WebUI：不再包含开发免授权文案或 `not_required` 成功态；缺失、错误和有效状态均有清晰入口与反馈。
- 回归：候选授权导入、机器码导出、健康检查、设置页刷新以及既有生产安装策略不退化。
- 全量：授权、凭据和鉴权属于高风险改动，运行项目规定的全量验证入口。

### 8.3 真实浏览器与 UX QA

在隔离源码运行环境中至少验证：

- 无授权打开设置页时显示“未安装授权”，不存在开发免授权文案；
- 机器码、导入和刷新入口可见、可键盘访问；
- 无授权发起聊天或专家团任务时被阻止，并获得具体可恢复的错误信息；
- 导入匹配当前机器的有效测试授权后状态变为“授权有效”，同一执行入口允许继续；
- 常用桌面视口下布局不退化，状态不只依赖颜色表达。

最终输出中文《前端 UX QA 报告》，未执行的截图、可访问性自动化或视觉回归必须明确标记为“未验证”。

## 9. 兼容性与迁移

- 现有有效 V3 离线授权无需迁移或重新签发；源码环境必须为当前机器准备同一签发体系下的有效授权。
- 原先依赖源码免授权的本地开发和端到端测试必须改用隔离测试授权夹具。
- 原先显式设置关闭授权变量的真实运行脚本必须删除该设置；若遗留覆盖，系统按安全错误失败关闭，而不是静默忽略。
- 不自动删除任何现有授权、设备身份或状态文件。

## 10. 完成标准

同时满足以下条件才可认为源码改动完成：

1. 仓库中不存在面向实际运行的开发免授权分支、文案或关闭授权开关；
2. 所有实际运行入口使用同一最终授权门禁；
3. 开发、测试和生产的策略字段及失败行为一致，仅受信资源位置随载体变化；
4. 授权核心、入口、WebUI 和全量验证通过；
5. 真实浏览器验证与中文《前端 UX QA 报告》闭合；
6. 最终 staged bytes 通过 Sol 审核后精确提交并正常推送 `main`；
7. Tag、Release、制包、安装、部署和目标机验收仍保持未授权、未执行状态。
