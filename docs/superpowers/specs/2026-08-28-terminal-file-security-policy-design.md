# 方案 2：终端与文件安全策略最小设计

日期：2026-08-28
状态：核心最小实施与源码全量验证已完成，待最终审核提交；超范围方案另存于本地 WIP 快照

## 目标

把安全判断从“父目录出现 group-writable 位即拒绝”收窄为真实威胁判断，同时不关闭命令审批、灾难性硬阻断、沙箱、JWT 校验、设备绑定或防时间回拨。

本阶段只处理六项核心合同，不建设完整目录授权产品、通用代码沙箱或复杂动态路径分析。

## 最小安全模型

### 1. 用户自有普通目录

- POSIX 当前用户拥有的 `0700`、`0755`、`0775` 普通目录均可使用。
- `world-writable`、错误 owner、符号链接分别返回不同原因。
- 不批量修改用户主目录权限；只有 Taiji 自己的私有状态叶目录可以按既有规则收紧。

### 2. Windows 对等语义

- 标准继承 DACL 可用。
- 错误 owner、危险跨用户写 ACE、reparse point 分别识别。
- 本阶段用纯合同测试锁定语义；不宣称真实 Windows 安装态已验收。

### 3. 安装态能力默认值

- 未配置时默认 `local_controlled`：terminal 与 execute_code 可用。
- 明确 `strict` 时保持关闭。
- 非空非法配置失败关闭到 `strict`，不得扩大能力。
- delegate 与未批准 skill script 不因 local_controlled 自动开启。

### 4. 授权状态错误

- 真实时间回拨继续返回 `license_clock_rollback` 和时间异常说明。
- 状态 JSON 损坏或内容完整性失败返回 `license_state_invalid`，不得出现“系统时间异常”。
- JWT 签名、设备绑定、过期和防回拨逻辑不删除。

### 5. 命令风险控制

- 保留既有危险命令识别与命令级审批。
- 保留灾难性命令硬阻断、管理员权限审批和 sudo 密码保护。
- 本阶段不引入全局 yolo，也不关闭系统安全产品或沙箱。

### 6. 测试收集

- `test_always_directory_approval_persists_only_canonical_directory` 必须位于 pytest 可收集层级。
- 修复只针对测试结构，不扩展目录授权 UI 或管理能力。
