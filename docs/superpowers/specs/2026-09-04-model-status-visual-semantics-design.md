# 模型配置状态视觉语义调整

状态：方案已获用户确认；源码实施与隔离浏览器验收已完成，目标机新安装态未验证。

## 目标与已确认问题

用户已确认新安装包的模型展示及“刷新本机状态”恢复正常，但截图中的“模型服务连接正常”仍配黄色大感叹号，造成故障误导。

在 `main@0e8c0319` 中，`static/panels.js` 的 `_renderModelConfigFocusSummary` 将 `connection_verified` 映射为 `tone: warn`，并将非成功、非刷新状态统一显示为感叹号。主区域还混合展示可选图片能力的待配置提示。

目标：用户能区分“连接检查成功”“尚未检查”“确需处理”和“实际对话成功”，文字、图标、颜色一致；可选能力不使主模型成功状态看起来异常。

## 方案选择

- 仅将连接正常改绿：改动最少，但保留其它中性状态被画成警告、可选图片状态混入主摘要的问题。
- 统一受影响状态语义（采用）：调整主模型摘要及图片能力摘要的状态映射与位置；不改变验证、保存、刷新行为或后端状态。

## 状态与展示合同

| 状态 | 展示 | 文案及行为边界 |
| --- | --- | --- |
| connection_verified | 绿色小勾；标题“模型服务连接正常”；相关主模型徽标同为成功色 | “连接检查已通过，可以开始对话。实际对话效果以会话结果为准。”不得显示“对话已验证” |
| chat_verified | 绿色小勾；“最近一次对话验证成功” | 保留真实对话验证的独立状态，不由刷新或连接检查升级 |
| configured_unverified | 中性信息图标与低强调样式 | “主模型已配置，尚未检查连接”；保留“检查连接”入口 |
| unsupported | 中性信息样式 | 说明该 Provider 暂不支持非生成式连接检查；不表述为服务故障 |
| runtime_refresh_pending / 正在检查 | 蓝色进度提示，刷新图标 | 明确区分“正在刷新本机状态”和“正在检查连接”；沿用原有禁用、防重复及草稿保护 |
| unconfigured（主模型） | 黄色警告与明确说明 | 缺少必需模型或凭据时引导配置，不能伪装为正常 |
| failed | 红色错误图标、原因与恢复提示 | 保留既有安全错误信息，不隐去真实问题 |
| 可选识图/生图未配置、未验证 | 图片能力区域的灰色次要信息 | 不放在主模型成功摘要里制造总状态异常；原配置、测试入口仍可发现 |
| 可选能力检查中、成功、失败 | 各自区域的进度、成功、错误样式 | 实际失败不能降为普通灰色；可选能力不改变主模型验证事实 |

主区域成功图标保持小型、克制，不增加动画或整页大面积高亮。不以颜色作为唯一状态信号；保留可见文字及现有状态播报。中性、进度、成功和失败样式均须显式定义，避免未命中的选择器回落为绿色。

## 范围与实现边界

预计修改 WebUI 的 `static/panels.js`、`static/style.css`、必要的 `static/index.html` 和对应模型状态测试。复用现有组件、状态来源及浏览器夹具，不增加依赖。

从主摘要移除的图片状态仍在图片能力区域显示，不能删除配置/测试入口。检查现有默认 HTML 和异步渲染，避免加载期间先出现绿色成功或黄色故障的错误闪现。

不改 Provider/模型配置规则、验证 API、凭据处理、业务状态枚举或安装脚本；不自动发起真实 Provider 请求。不执行制包、安装、部署、签名或发布。
