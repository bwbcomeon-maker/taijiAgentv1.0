# 深度材料研究团收敛优化执行计划

## 目标与责任边界

本计划以 `bounded_report_v1` 作为新建 research v3 任务的冻结执行策略，取代旧方案中围绕单篇样例反复自动审核和返工的安排。

产品必须保证：

- 六阶段实际执行且前序材料正确传递。
- 央国企或政府内部调研材料的结构、语气和措辞进入提纲、分章写作、汇总和审核。
- 标准正文目标 8,000–12,000 字，采用真实正文计数；明显不足时最多一轮定向补写。
- 一轮审核后结束流程，保存正文和审阅意见，结果可查看、可导出 Word。
- 篇幅不足、资料不足或有事实阻断时如实标识，不得标成正式等级。

模型决定观点深度、论证水平、文笔和每次实际篇幅；不因这些差异继续扩展程序修复。

## 冻结行为

### 正式报告骨架

1. 调研背景与目的
2. 基本情况
3. 主要问题及原因
4. 分析研判
5. 对策建议
6. 推进安排及需研究事项

实践借鉴、方案比较和适用条件只在题目和可信材料支持时作为分析研判的子节。正文不得出现 `source_id`、`claim_id`、冻结 Brief 或内部任务指令。

### 篇幅与审核

- `standard`：8,000–12,000 字，目标约 10,000 字。
- `deep`：15,000–20,000 字，只在用户明确选择时使用。
- 正文计数排除封面、目录、摘要、来源表、附录和内部元数据。
- 完整初稿明显不足时，只对分析、比较和建议章节执行一轮补写；不得开始第二轮。
- 新策略自动内容修订次数为 `0`。审阅意见不自动触发整篇重写。
- 用户明确提出修改时，只复用已有定向修订入口，不自动进入再审核循环。
- 篇幅或主观质量门槛未通过时，仍允许保存和导出明确标识的工作草稿；不得赋予 `formal_research_report` 等级。
- 虚构事实、伪引、关键矛盾、缺章、正文丢失、身份串用和导出失败继续作为工程或事实阻断。

## 兼容边界

- 沿用现有启动 API、`writing_style`、`depth`、六阶段标识和文档导出入口。
- 新建 research v3 任务在冻结的 `research_writing_contract` 中保存 `execution_policy="bounded_report_v1"`。
- 无该标记的历史任务保持冻结语义，不批量迁移，不直接改写历史运行 JSON。
- 不新增页面、公开参数、底层编排、通用评分器、新模型接入或无限重试框架。

## 验证与收尾

1. 工程验证：新策略冻结、历史兼容、真实字数门槛、一次补写、审核终止、事实阻断、回执身份/幂等/输入失效/恢复及 DOCX 一致性。
2. 真实验收：先跑央国企。2026-09-08 用户明确同意“改为短流程，尽快收尾”，政府与资料不足合并为短流程，不再生成第二篇完整长报告；完整政府长报告标为未验证。短流程成功或阻断须如实记录，不能以启动成功代替产出验收。
3. 每个真实任务记录任务标识、六阶段产物、实际正文字数、是否补写、结果等级、审阅意见、DOCX 路径和 WPS 打开记录。
4. 前端受影响路径按项目内 `frontend-ux-qa` Skill 执行真实浏览器/Electron 验收并输出中文 QA 记录。
5. 收尾顺序：相称本地验证 → 精确暂存 → Sol 审核完整 staged 候选 → commit → 刷新远端 → 正常 push `main`。

本轮不包含制包、安装、部署、签名、Tag、Release 或发布。
