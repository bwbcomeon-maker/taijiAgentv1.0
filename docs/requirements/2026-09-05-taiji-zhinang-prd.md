# 太极智囊产品需求文档（PRD）

版本：V1.0 实现依据稿 · 日期：2026-09-05 · 产品入口：智囊库

本文件把已确认设计稿转为可开发、可验收的产品契约。本文中的“必须”“应”描述待实现要求，不代表当前产品已经实现。本轮交付为 PRD 和设计附件，不包含业务代码实现、安装或发布。

## 1. 产品结论与目标

在当前 Taiji Agent 内增加“智囊库”，把 Agency Agents 开源角色内容转化为可发现、可理解、可直接用于任务的 AI 角色。用户找到合适角色后，在现有聊天工作台创建新任务，补充需求、发送消息，获得基于该角色工作方法的帮助。

产品名称为“太极智囊”，主导航名称为“智囊库”。它与已有“专家团”并列：智囊服务于单角色普通任务；专家团继续承担已有的固定团队、分阶段协作及文档交付流程。本期不让两套流程互相替代。

“所有功能可用”的定义：本 PRD 范围内每个入口均有真实行为、持久状态和失败反馈，角色指令真正进入模型执行链，且后续对话、重试和恢复保持一致。不是只做六张静态卡片，也不是承诺每个开源角色自带外部工具、专业资质或确定性的业务结果。

### 1.1 可观察的完成标准

1. 用户能通过中文角色信息、分类和搜索找到角色，查看完整职责、示例、限制和来源。
2. 收藏跨刷新及应用重启保留；最近使用来自真实任务记录，不是预置假数据。
3. “使用此智囊”创建绑定该角色的新任务，但不自动发送消息、不自动调用模型或工具。
4. 用户发送需求后，现有聊天、附件、流式输出、取消和结果展示正常工作；角色在任务生命周期内不丢失、不串到其他任务。
5. 现有品牌、导航、模型配置、普通聊天及专家团流程不被破坏。
6. 用户排除的三个功能不出现；加载、空态、错误、重试、键盘操作和窄屏路径可验收。

### 1.2 目标用户与核心任务

| 用户 | 任务 | 期望价值 |
| --- | --- | --- |
| 售前、方案及投标人员 | 澄清客户需求、整理方案和响应策略 | 少写角色提示词，快速进入工作 |
| 产品及研发人员 | 梳理需求、评估架构、制定实施路径 | 得到结构化分析和检查清单 |
| 内容及运营人员 | 策划选题、梳理表达、组织材料 | 使用可复用的专业工作方法 |
| 已有产品用户 | 为当前工作找一个合适的 AI 角色 | 不离开现有模型、工作区和任务体系 |

### 4.1 页面结构与视觉

4. 右侧展示选中角色详情。真实初始态不强制选中首项；用户点开详情后高亮对应卡片。
5. 桌面宽屏可采用侧栏 + 卡片区 + 非模态详情栏；中等宽度采用覆盖式详情抽屉；窄屏使用单列卡片和全宽详情层，分类改为可展开控件。不得为保持四栏而挤出横向滚动。

“设计预览”“示例角色”等仅用于设计稿的标记在正式页面移除。不得展示虚构星数、装机量、角色数量或“专家资质”标识。

### 4.2 筛选语义：消除两处“全部角色”的歧义

筛选由三个正交条件构成：范围（全部/收藏）× 工作领域（全部/某领域）× 视图（精选/全部/最近），再叠加搜索词。UI 必须明确当前条件，并提供“清除筛选”。

- 二级导航“全部角色”：重置范围为全部、领域为全部、视图为全部，清除搜索。它是回到完整目录的入口。
- “我的收藏”：切换收藏范围，重置领域为全部、视图为全部、清除搜索；之后可继续搜索或选择领域。
- 领域入口：在当前范围内切换领域，保留搜索词，将视图切到全部，避免因精选或最近筛选导致误以为领域为空。
- 主区“精选角色 / 全部角色 / 最近使用”：只切换视图，保留范围、领域、搜索词。收藏范围内的精选和最近是交集，不是另一个目录。
- 首次进入默认“全部范围 + 全部领域 + 精选”；二级导航的“全部角色”表示当前全部范围，并辅以主区视图明确精选状态。
- 搜索覆盖中文名称、原名、摘要、标签和能力关键词；忽略大小写与首尾空白，不承诺语义检索。查询不匹配整段原始提示词，避免不相关结果。
- 精选由版本化内容清单人工指定并排序；全部按目录顺序稳定排序；最近按最后受理任务时间倒序。相同时间以角色 ID 稳定排序。
- 每页 24 项，展示当前结果数、上一页/下一页及页码；筛选变化回到第一页。图中的六张卡片不是目录规模上限。
- 查看详情不改变筛选；关闭详情恢复列表位置和触发焦点。筛选使当前角色移出结果时关闭详情，避免错误高亮和误用角色。

## 5. 逐项功能契约

### 5.1 卡片与角色详情（F06、F07）

卡片显示中文名称、工作领域、一句话用途、最多两个交付类型标签、收藏状态和“查看详情”。点击卡片非按钮区域或“查看详情”打开同一详情；点击收藏不同时打开详情。卡片与详情的收藏状态同步。

详情必须包含：

- 名称及“AI 角色”标识；简短用途、适用任务和不适用范围。
- “能帮你做什么”：由该角色内容支持的 3–5 条能力，不添加未接入的工具承诺。
- “试着这样开始”：至少一个可选择的任务示例及“使用此示例”操作。
- 详情不展示交付示例、原始角色说明、适配说明、上游来源和完整 MIT 许可证；这些内部字段仍可用于角色入库、审计和任务快照，不进入面向用户的详情界面。
- 需要联网、特定文件工具或专业复核的角色应显示条件提示；用户无相关能力时，仍可进行文字分析，但不能宣称已执行外部操作。
- 底部主按钮“使用此智囊”；说明“将创建新任务，补充需求后开始”。

设计稿六张角色卡的内容映射建议如下。文件存在性已核查；正式展示文案及有效提示词必须在入库时逐条与冻结源文件对照，不能只根据文件名推定能力。

| 展示角色 | 上游相对路径 | 入库注意 |
| --- | --- | --- |
| 售前方案顾问 | `sales/sales-engineer.md` | 聚焦需求澄清、技术方案与 PoC，不承诺自动生成并验证客户方案 |
| 投标策略顾问 | `sales/sales-proposal-strategist.md` | 聚焦响应策略，不冒充已接入全套投标编制和评分校验流程 |
| 产品经理 | `product/product-manager.md` | 梳理需求、优先级、范围与验收 |
| 技术架构顾问 | `engineering/engineering-software-architect.md` | 方案分析与取舍；代码执行仍由已有工具与权限决定 |
| 内容策划顾问 | `marketing/marketing-content-creator.md` | 选题与内容结构；不伪造已发布或传播数据 |
| 文档审阅助手 | 本地明确改编的 `taiji:document-reviewer` | 保留设计名称，提供通用逻辑、遗漏和一致性审阅；不能直接把 `specialized/legal-document-review.md` 换名当通用文档审阅。若借鉴该文件，须标注衍生关系，并删除无依据的专业能力承诺 |

上游法律审阅角色单独保留准确的法律用途和复核提示；通用“文档审阅助手”作为只读、随产品分发的本地角色，不产生用户端管理入口。

### 5.2 收藏（F04）

- 使用明确的“收藏 / 已收藏”状态及可读名称；可从卡片或详情切换。
- 服务端持久化为权威数据，按当前配置档案隔离；浏览器本地缓存仅可用于加速。
- 请求中防重复提交；失败保持/恢复原状态并提供可重试提示，不能仅在前端假成功。
- 首次没有收藏时显示“还没有收藏，找到常用角色后点击收藏”及“浏览全部角色”。
- 多窗口再次进入或窗口恢复焦点时刷新；同角色最后成功的设置结果生效，不用非幂等 toggle 接口。
- 角色随产品升级下架时保留收藏关联，在收藏范围显示“当前版本未提供”的条目，可取消收藏，不允许创建新的失效角色任务。
- 收藏时保留最后已知的名称、主分类、标签和用途摘要；目录仍有该角色时展示当前信息，下架后用保留信息搜索和匹配领域。失效条目不进入精选，只有存在可见历史任务时进入最近视图；详情只显示保留信息、失效原因和取消收藏，不伪造可读的完整原文。若有历史任务，另提供进入该任务的入口。

### 5.3 最近使用（F05）

“使用”以角色任务的用户消息通过校验并被聊天执行链受理为准。仅浏览、收藏、创建空任务、预填草稿不计入最近；受理后模型或工具失败仍计入真实尝试。

- 每个角色显示最近受理时间和最近可访问任务；提供“继续最近任务”，与“使用此智囊”创建新任务区分。
- 使用信息取自角色会话元数据，不能套用技能使用统计；同一受理请求重试不得重复计数。
- 作用域遵循现有会话的配置档案和可见性，不跨档案暴露任务标题或内容。
- 删除任务后不再跳转到该任务，回溯该角色其他可见任务；全部删除则角色移出最近列表。普通刷新不改变排序。
- 上游角色移除后，已有任务仍可通过其固定快照继续，最近条目注明“当前目录已移除”；创建新任务按钮不可用并说明原因。

### 5.4 使用与示例任务（F08、F09）

正常路径：选择角色 → 查看详情 → 使用此智囊 → 创建绑定角色的新任务 → 用户补充需求或附件 → 手动发送 → 现有聊天执行。

1. 点击主按钮时，先完成当前任务草稿保存；失败不离开、不覆盖用户输入。
2. 服务器校验角色存在、版本匹配、来源文件/有效提示词可读，以及配置档案、工作区和项目标识是否合法且可访问。尚未配置模型允许创建角色任务，在发送时阻止执行并引导配置；非法标识或访问越界在创建时拒绝。创建操作不调用模型。
3. 创建请求携带稳定请求 ID；前端禁用重复点击，服务端对同一请求幂等，超时后重试返回同一任务，避免产生多个“未命名任务”。
4. 继承用户此刻选择的模型、提供方、配置档案、工作区和项目，按现有新会话规则执行；角色不得私自改模型、切换提供方、开启 worktree 或改变工具授权。
5. 新任务显示固定的角色标签和“查看角色说明”入口，焦点进入输入区；默认空白，不自动把完整角色原文塞进可见用户消息。
6. “使用此示例”走相同的新任务流程，并将所选示例预填为新任务草稿；仍由用户手动发送。连续点击应幂等，不反复生成任务。
7. 创建失败留在详情并显示可理解原因。模型未配置时进入任务后沿用现有配置校验与引导，不承诺可以直接执行；不得跳到真实 Provider/OAuth 页面。
8. 无消息、无草稿的任务沿用当前不落盘策略。输入草稿后按现有草稿规则保存；首次消息写入时，角色绑定与消息必须一致持久化。
9. 用户从普通“新建聊天”进入时不继承上个任务角色；一个任务只绑定一个角色。本期不提供中途换角色，需另建任务。

### 5.5 任务内角色一致性（F10、F11）

- 角色指令在模型请求的系统上下文中生效，而非仅用于卡片、任务标题或第一条用户消息。
- 智囊任务以不可变角色快照替代普通会话的可选 `personality` 内容；不把两个角色无序叠加。普通任务现有 `personality` 行为保持不变。
- 智囊任务内不提供可成功修改但不生效的人格控件：现有人格切换入口禁用并说明“此任务使用固定智囊角色，如需更换请新建任务”；`/api/personality/set` 对角色绑定任务拒绝冲突设置并返回明确错误。普通任务的控件和接口行为不变。
- 工作区约束、品牌隐私、安全规则、用户授权和进度反馈等原有系统上下文不得因新增角色而丢失。角色文本不能修改工具权限，也不能自行启动多 Agent。
- 继续对话、重试最后一轮、流式重连、会话恢复、上下文压缩和缓存 Agent 复用时均采用同一快照。若现有功能产生同一任务的分支或复制，必须复制角色绑定；普通独立新任务不复制。
- 清空消息但保留同一任务时保留角色；删除任务则删除任务绑定。角色标签与实际有效快照一致。
- 产品更新不能改变已有任务的角色指令。新任务采用当前目录版本；旧任务继续采用创建时快照，即使源角色已移除。
- 快照损坏或缺失且无法按绑定版本恢复时，禁止悄悄降级为普通聊天，明确提示不能继续并允许另建任务；不得用新版提示词静默替代。
- 现有专家团的严格执行通道不被普通智囊注入逻辑接管；不得因共用流式执行代码改变专家团行为。
- 上传、读取、生成和下载文件复用当前已支持的能力。实际文件生成成功后才显示产物入口；不因角色名称而新增对所有 Office/PDF 格式的支持承诺。

## 7. 与现有系统的实现衔接

本节是基于当前结构的最小建议，不授权无关重构。实际实施先写聚焦契约测试，再实现，按项目生命周期完成验证与收尾。

### 7.1 接口契约建议

| 接口 | 行为 | 关键约束 |
| --- | --- | --- |
| `GET /api/zhinang/catalog` | 返回元数据、筛选结果、总数、页码及目录版本 | 不返回全量角色提示词；只读，支持范围/领域/视图/关键词 |
| `GET /api/zhinang/roles/{role_id}` | 返回角色详情、原文、示例、边界和来源 | ID 作为整体 URL 编码；通过清单查找，不把请求值拼成任意文件路径 |
| `GET /api/zhinang/session-role?session_id=…` | 返回指定任务绑定的历史角色详情 | 校验任务访问边界，从历史详情快照读取，不依赖当前目录，不暴露内部有效系统提示词 |
| `PUT /api/zhinang/favorites/{role_id}` | 明确设置 `favorite: true/false` | 幂等；校验档案访问边界；允许取消已移除角色的收藏 |
| 扩展 `POST /api/session/new` | 可选 `zhinang_role_id`、`catalog_version`、`request_id` | 服务端固定快照再返回；无角色参数时兼容原有行为；禁止客户端直接提交系统提示词 |
| 现有任务读取/聊天接口 | 返回公开角色标签；执行时解析固定快照 | 列表、详情、流结束同步、跨窗口和恢复投影保持一致 |

不存在的角色返回明确的未找到错误；目录版本过期返回可刷新重试的版本冲突；配置或参数不合法走现有校验；存储冲突提供可恢复错误，不泄露物理路径和内部异常。所有新接口沿用现有本地访问控制与隐私过滤，不能因角色库是开源数据而放宽权限。

新任务幂等规则：同一配置档案与 `request_id` 绑定规范化创建参数；相同参数返回同一会话，不同参数返回冲突。进程内需防并发创建；空任务保持现有内存生命周期，服务重启使其失效后可重新创建。已有草稿或消息的持久会话须保存关联信息，重启后的请求重放能定位原任务。不要为幂等引入永久空任务文件。

### 7.3 技术必须守住的约束

1. 不将全部角色原文一次性注入模型；每个任务只加载其选中角色有效快照，避免成本和上下文浪费。
