# 统一运行时授权功能契约

验证对象：太极智能体源码、测试、候选和安装运行形态的统一离线授权策略，以及“设置 → 模型配置 → 授权管理”的状态、机器码导出、授权导入和恢复入口。

## 用户目标

所有真实运行环境采用同一授权与鉴权模式。环境名称、源码模式、启动脚本或环境变量不能让未授权实例进入可执行状态；只有固定签名、V3 机器绑定、有效期、版本和时钟检查全部通过的授权才是“授权有效”。

## 状态合同

| 权威状态 | 页面状态 | 引导/诊断 | 执行结果 |
|---|---|---|---|
| `valid` | 授权有效，绿色边框和 `✓`，同时显示文字 | ready | 允许继续进入模型/Provider 检查 |
| `missing` | 未安装授权，错误态和 `!` | action required / blocked | 阻止真实执行，提示导出机器码或导入授权 |
| `expired` | 授权已到期，错误态和 `!` | action required / blocked | 阻止真实执行 |
| `invalid` / `blocked` | 授权无效或不可用，错误态和 `!` | action required / blocked | 阻止真实执行 |
| `not_required`、`required=false`、未知或校验异常 | 不得显示成功；统一为警告或不可用 | 不得 ready | fail closed |

## 安全与兼容边界

- 运行时固定要求授权、V3 强机器绑定、固定公钥指纹、固定产品版本、有效期和时钟回拨检查；安全环境变量覆盖被拒绝。
- 授权、状态和设备文件固定在当前系统账户的 canonical profile 中；启动器只可读取公开诊断路径，不能把路径作为运行时覆盖注入子进程。
- `install_license_token()` 以内存中的同一 token 完成固定策略校验，通过后调用现有跨平台安全原子写入，再安全读回并做常量时间内容核对；最终返回 canonical `load_license_status()`，因此导入响应与真实执行门禁一致。
- 无效、空、超限或策略覆盖输入在写入前失败；写入/读回异常使用固定脱敏错误。WebUI 响应和日志均不记录 token、私钥路径或账户授权路径。
- Electron 自动化仅在临时 OS-account profile 中使用仓库测试签名器；产品子进程不继承私钥、授权关闭变量或测试钩子，成功和失败均显式清理临时授权。
- Windows 临时账户隔离、真实 Chromium、本机 Electron 页面、Linux/Kylin/UOS 安装态、发布制品和部署不在本轮已验证范围。
