# 主模型配置权威对账功能契约

验证对象：`codex/linux-golden-template-v1` 分支中太极智能体“设置 → 模型配置 → 主模型”的保存、运行时刷新与超时对账流程。

## Contract Routing

- 任务类型：主模型配置持久化后的前端状态一致性修复。
- 涉及区域：`api/model_config.py`、`static/panels.js` 及对应 API/前端测试。
- 相关公开约束：项目 `AGENTS.md`、`docs/runbooks/development-lifecycle.md`、Hermes WebUI `AGENTS.md`、`docs/CONTRACTS.md`、`docs/UIUX-GUIDE.md` 和 `DESIGN.md`。
- 状态边界：本轮只调整主模型保存结果的公开状态与页面对账；不改变聊天密钥解析、凭据持久化、识图/生图配置或路由语义。

## 用户目标与六态合同

用户保存主模型配置后，页面必须准确区分以下六种状态，不能把“浏览器没有及时收到响应”等同于“保存失败”：

| 状态 | 进入条件 | 用户文案与反馈 | 允许的后续动作 |
|---|---|---|---|
| 未配置 | 权威配置缺少 Provider、模型或可用凭据 | 主模型尚未配置完整，并说明需要补充的配置 | 编辑并保存 |
| 保存中 | 已发出一次保存请求，尚未得到确定结果 | 正在保存主模型配置 | 保存按钮禁用且 `aria-busy=true` |
| 刷新中 | API 确认当前 `main_request_id` 已提交，且 `runtime_state=refresh_pending` | 配置已保存，运行时正在刷新；不能显示为“待配置” | 刷新状态或重启后核对，不重复保存密钥 |
| 待核对 | 保存请求超时、5xx 或其它结果不确定 | 保存结果待核对，正在读取本机权威状态 | 自动执行一次只读 GET；不自动重发 POST |
| 已生效 | 权威状态的 `main_request_id` 精确匹配本次请求，Provider、模型、Base URL 和凭据状态匹配，且运行时没有待刷新项 | 主模型已生效，可以开始新会话 | 关闭编辑区或继续使用 |
| 保存失败 | 服务端以 4xx 明确拒绝，或权威回执不匹配、证明本次请求未提交或已被覆盖 | 主模型配置保存失败，并保留可操作的错误说明 | 修正输入后再次保存 |

## 安全与兼容边界

- 不增加、延长或全局放宽 `workspace.js` 的 30 秒默认超时。
- 主模型保存 POST 逐请求禁用底层网络错误重试，避免同一密钥写入产生重复或竞态提交；其它 API 的既有重试与全局 30 秒超时保持不变。
- 正式 UI 每次保存都使用 `crypto.getRandomValues` 生成新的 128-bit 小写十六进制 `request_id`，不使用 `Math.random`；兼容内部调用时，服务端可生成相同格式的 ID。
- 服务端在同一 config/`.env` 原子事务中把回执写入顶层内部键；当前已提交 ID 不可再次使用。GET/POST 只公开非秘密 `main_request_id`。
- 对账 GET 只接收脱敏公开投影；前端不缓存密钥、密钥摘要或完整凭据响应，只有回执和公开主模型状态同时匹配才可判定生效。
- 不覆盖识图、生图、平台凭据编辑器及其未保存草稿。
- 不改变 `/api/model-config/main` 的路由或密钥持久化顺序；新增可选非秘密 `request_id`，正式 UI 必须发送，旧内部调用缺失时由服务端安全生成。
- 该契约只证明当前功能分支的行为；正式 `main`、DEB、麒麟安装态和真实 Provider 调用另行验收。
