# 主模型配置权威对账功能契约

验证对象：`codex/model-config-receipt-review-fix` 分支中太极智能体“设置 → 模型配置 → 主模型”的保存、运行时刷新、结果不确定对账与凭据回执失效流程。

## Contract Routing

- 任务类型：主模型配置持久化后的前端状态一致性与回执可信性修复。
- 涉及区域：`api/model_config.py`、`static/panels.js`、`static/index.html`、Agent 共享凭据事务层及对应 API/前端/凭据事务测试。
- 相关公开约束：项目 `AGENTS.md`、`docs/runbooks/development-lifecycle.md`、Hermes WebUI `AGENTS.md`、`docs/CONTRACTS.md`、`docs/UIUX-GUIDE.md` 和 `DESIGN.md`。
- 状态边界：本轮不改变聊天路由、识图/生图配置或全局超时；只增加非秘密回执修订元数据，并让已有正式凭据写入路径在实际改变当前主模型密钥时原子失效旧回执。

## 用户目标与六态合同

用户保存主模型配置后，页面必须准确区分以下六种状态，不能把“浏览器没有及时收到响应”等同于“保存失败”：

| 状态 | 进入条件 | 用户文案与反馈 | 允许的后续动作 |
|---|---|---|---|
| 未配置 | 权威配置缺少 Provider、模型或可用凭据 | 主模型尚未配置完整，并说明需要补充的配置 | 编辑并保存 |
| 保存中 | 已发出一次保存请求，尚未得到确定结果 | 正在保存主模型配置 | 保存按钮禁用且 `aria-busy=true` |
| 刷新中 | API 确认当前回执已提交，且 `runtime_state=refresh_pending` | 配置已保存，运行时正在刷新；不能显示为“待配置” | 刷新状态或重启后核对，不重复保存密钥 |
| 待核对 | 保存请求超时、5xx 或其它结果不确定，且权威 GET 暂时失败 | 保存结果仍待核对，提示点击现有“刷新状态” | 同一页面生命周期内继续相同 request ID 的只读 GET；不重发 POST |
| 已生效 | 权威回执精确匹配本次请求，Provider、模型、Base URL 和凭据状态匹配，且运行时没有待刷新项 | 主模型已生效，可以开始新会话 | 关闭编辑区或继续使用 |
| 保存失败 | 服务端以 4xx 明确拒绝，或权威回执/公开投影不匹配，证明本次请求未提交、密钥未配置或已被后续更新覆盖 | 主模型配置保存失败，并保留可操作的错误说明 | 修正输入或确认最新状态后再次保存 |

## 安全、事务与兼容边界

- 不增加、延长或全局放宽 `workspace.js` 的 30 秒默认超时。
- 主模型保存 POST 逐请求禁用底层网络错误重试，避免同一密钥写入产生重复提交；其它 API 的既有重试合同不变。
- 正式 UI 每次保存使用 `crypto.getRandomValues` 生成新的 128-bit 小写十六进制 `request_id`，不使用 `Math.random`；旧内部调用缺失 ID 时仍由服务端生成相同格式的 ID。
- 服务端在 config/`.env` 原子事务中写入 request ID、绑定的密钥环境变量名及随机 UUID4 十六进制凭据修订号。修订号不由密钥计算，不是密钥哈希，也不能用于推导密钥。
- GET 只有在 request ID、绑定环境变量、回执修订号和该环境变量的当前修订号全部合法且一致时才公开 `main_request_id`；旧版没有修订绑定或元数据损坏的回执失败关闭。
- Agent 共享 `mutate_config_strict` / `mutate_env_unique` / `mutate_config_env_strict` 正式写路径在主模型公开投影或实际生效凭据改变、删除时移除旧主模型回执；环境变量密钥实际变化时同时轮换对应修订。写入同一个值、仅修复重复行但最终生效值不变、或修改无关配置/Provider 不误失效。只有主模型成对提交入口可创建新回执，普通 config-only 写入不能伪造可信回执。
- 需要同时改变密钥和回执时，二者共用现有持久化事务和恢复日志；准备/日志失败时不得只发布其中一项。
- 页面只在当前页面生命周期内保留待核对所需的 Provider、模型、Base URL 和 request ID；不保留 API Key、密钥摘要或完整凭据响应。刷新整个页面后不声称仍能证明原请求，只展示新的权威配置状态。
- 对账只接收脱敏公开投影；只有回执和公开主模型状态同时匹配才可判定生效。
- 不覆盖识图、生图、平台凭据编辑器及其未保存草稿。
- 该契约只证明当前功能分支的源码自动化行为；正式 `main`、DEB、麒麟安装态、真实浏览器和真实 Provider 调用另行验收。
