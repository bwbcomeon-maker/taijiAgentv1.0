# Windows 安全设置保存前端 UX QA 报告

## 结论

**带限制通过。** 源码与隔离浏览器层已证明“选择安全模式 → 保存 → 显示需重启提示”的主路径可用，Windows 专用持久化和启动读取有自动化覆盖；用户 Windows 已安装版本尚未更新和验收，因此不能宣称安装态已修复。

## 功能契约

| 项目 | 结果 |
| --- | --- |
| 入口 | 设置 → 系统 → 安全模式 |
| 角色 | 桌面端本机用户 |
| 主操作 | 选择企业安全或本机调试，按需勾选两项扩展能力并保存 |
| 成功反馈 | 显示已保存、关闭并重新打开后生效；接口状态区分当前值与已保存值 |
| 失败反馈 | 使用允许列表内的“安全设置保存失败，请重试。”，不暴露内部异常 |
| 重启契约 | Windows 启动器仅加载固定 schema 与允许字段；异常文件回落企业安全 |

## 验证证据

| 层级 | 结果 | 证据 |
| --- | --- | --- |
| 后端写入 | 通过 | Windows 分支不调用凭据写入器；覆盖首次保存、仅改基础策略时保留扩展选择、替换失败时保留旧文件并清理临时文件 |
| 启动读取 | 通过 | 覆盖有效保存值、构建器集成、无效文件闭合到企业安全、首次无文件保留已规范化开发策略 |
| UI 静态契约 | 通过 | 状态渲染、保存结果、成功/失败文案断言通过 |
| 隔离浏览器 | 通过 | 1280×900、768×900、390×900 三档视口；每档把安全模式从企业安全切换为本机调试，验证一次预期失败后仍保留草稿、一次成功后显示重启提示，POST 均携带 `local_controlled`，无页面错误；桌面与窄屏未见遮挡、横向溢出或操作不可达 |
| 完整门禁 | 通过 | `./scripts/verify.sh --full` 使用 Node v24.19.0；最终 `verification: PASS` |

## 可访问性与视觉检查

- 表单标签、下拉框、复选框和保存按钮均可发现；状态提示不只依赖颜色。
- 390 px 窄屏下控件保持纵向可读，保存操作可触达。
- 本轮没有改动视觉样式；未执行 axe 自动扫描和像素级视觉回归，标记为**未验证**。

## 剩余验收

- **Windows 安装态未验证**：需另行授权生成候选安装包并在真实 Windows 执行“保存 → 完全退出 → 双击重开 → 核对状态与权限”。
- 本报告不作为 Windows 制包证据；候选制包状态以独立流水线 run 为准。安装态验收、签名和发布仍未验证。
