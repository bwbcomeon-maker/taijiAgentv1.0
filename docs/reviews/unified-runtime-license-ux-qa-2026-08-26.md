# 前端 UX QA 报告：统一运行时授权

## 状态

带限制完成（当前 `main` 工作区源码与自动化范围）。核心策略、启动链、WebUI 状态投影和授权导入已实现并通过专项测试及独立复审；真实 Chromium/Electron 页面、截图、键盘/读屏、自动可访问性、视觉回归和安装态均未验证。

## 影响页面、组件与用户路径

- 页面：设置 → 模型配置。
- 组件：授权状态卡片、授权客户/到期/本机/来源信息、导入授权、导出机器码、刷新状态。
- 主路径：打开设置查看授权 → 缺授权时导出机器码 → 获得离线授权 → 导入 → 刷新为授权有效 → 再继续模型调用。
- 阻断路径：聊天或专家执行前发现授权缺失、过期、无效或校验异常 → 不创建真实 Agent 流 → 保留可理解的本地错误和恢复入口。

## 主内容 / 辅助内容 / 高级内容

- 主内容：授权是否有效，以及当前是否允许继续执行。
- 辅助内容：授权客户、到期时间、本机匹配、授权来源和错误说明。
- 高级/恢复内容：机器码导出、离线授权导入和手动刷新。

## 本轮变更

- 删除“开发环境无需授权”“开发源码模式无需授权”和 `not_required` 成功展示。
- 所有环境只有 `valid` 显示“授权有效”、绿色成功态和 `✓`；其它状态使用错误或警告文字及 `!`，不只依赖颜色。
- onboarding 只有有效授权为 ready；diagnostics 只有有效授权为 ready，缺失/无效/过期/阻断为 blocked，其它为 degraded。
- WebUI 授权导入改为调用核心公共安全安装接口，不再自行创建路径候选和替换文件。
- 启动器不再向 Agent/WebUI 注入授权文件、状态文件或开发关闭开关；Electron smoke 使用临时账户授权且结束即清理。

## 已自动化验证的用户路径

1. `valid` 显示授权有效；`missing`、`expired`、`invalid` 和未知状态不显示成功。
2. `not_required` 和 `required=false` 在设置引导与产品诊断中都不能进入 ready。
3. 缺失或失效授权在真实执行入口前被阻止，并生成可恢复的授权错误。
4. 无效、空、超限授权导入返回失败且不覆盖已有授权。
5. 有效 token 在内存中校验后写入 canonical 授权路径，读回内容一致才继续。
6. 导入后重新应用 canonical 时钟/状态检查；损坏状态或未来时钟不会先返回成功再立即失败。
7. 导入异常的 HTTP 响应和日志不包含测试 token 或私有路径。
8. Electron 测试夹具清除大小写变体的覆盖变量、私钥路径和 Python 钩子；成功、启动失败和进程退出都有清理证据。

## 空 / 加载 / 错误 / 成功 / 禁用 / 破坏性状态

- 空状态：未安装授权时显示“未安装授权”，并提供机器码、导入和刷新入口。
- 加载状态：沿用现有授权状态加载/刷新反馈；真实浏览器时序未验证。
- 错误状态：缺失、过期、无效、阻断和校验异常均不显示成功；后端使用脱敏提示。
- 成功状态：仅 canonical `valid` 显示“授权有效”。
- 禁用状态：导入/刷新期间的真实按钮禁用与忙碌时序未做浏览器验证。
- 破坏性状态：无授权导入不是删除操作；无效候选在写入前失败，不能覆盖现有授权。

## 剩余风险与边界

- 当前结果不能证明真实浏览器中的按钮焦点、布局、Toast 时序、横向溢出或屏幕阅读器体验。
- 当前结果不能证明 Windows、macOS 安装包或 Linux/Kylin/UOS DEB 中的真实账户目录、权限和二次启动行为。
- 代表性 Electron smoke 证明的是当前源码测试夹具，不等同于正式安装制品或目标机验收。
- 本轮不创建 Tag/Release，不制包、不安装、不部署，也不把本地 `main` 开发状态描述为稳定发布。
