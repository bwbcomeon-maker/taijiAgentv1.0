# 前端 UX QA 报告：主模型配置权威对账

## 状态

带限制完成（当前功能 worktree 的源码与自动化范围）。真实 Chromium/Electron、截图、自动可访问性、视觉回归、正式 `main`、DEB 和麒麟安装态均未验证，因此本报告不能声明真实安装态不存在 P0/P1，也不能替代后续目标机验收。

## 变更范围

- 主模型保存成功响应公开脱敏字段：`commit_state=committed`、`runtime_state=applied|refresh_pending` 与非秘密 `main_request_id`。
- 每次保存使用安全随机的 128-bit request ID；服务端把回执绑定到随机、非秘密的凭据修订号，不保存密钥或密钥摘要。
- 现有 Provider/Agent 正式凭据写入路径若实际改变或删除当前主模型密钥，会在同一 config/`.env` 事务内失效旧回执；同值写入和无关 Provider 更新不误失效。
- 保存请求超时、5xx 或结果不确定时，页面进入“待核对”，清空主模型密钥输入，只读取一次权威配置，不自动重放 POST；4xx 仍是确定拒绝。
- 首次权威 GET 失败后，同一页面生命周期内保留不含密钥的待核对信息；用户点击现有“刷新状态”时继续同一个 request ID 的 GET，不再发送 POST。
- 权威对账只合并主模型必要公开投影，不覆盖识图、生图和平台凭据的未保存草稿。
- 保存和手动对账期间，相关按钮禁用并设置 `aria-busy=true`，结束后恢复。

## 主要用户目标

用户保存主模型配置后，即使浏览器等待超时，也能通过同一笔请求的权威回执判断新密钥是否真正提交；临时读取失败时可以使用现有“刷新状态”继续核对，不会重复提交密钥或丢失其它配置草稿。

## 主内容 / 辅助内容 / 高级内容

- 主内容：主模型是否正在保存、需要核对、正在刷新、已经生效或确实失败。
- 辅助内容：Provider、模型、Base URL 与脱敏凭据配置状态。
- 高级内容：识图、生图和平台凭据编辑器；本轮确保它们的草稿不被主模型对账覆盖。

## 已自动化验证的主要用户路径

1. 保存开始：按钮禁用并暴露忙碌语义，页面显示“正在保存”。
2. POST 明确成功且运行时已应用：回执和公开投影都匹配才显示“已生效”。
3. POST 明确成功但运行时待刷新：显示“刷新中”，不显示“待配置”。
4. POST 返回 request ID 但 `configured=false`：不得误报生效，转入权威 GET；若仍不匹配则失败。
5. POST TimeoutError、fetch `TypeError` 或 5xx：不重放 POST，清空密钥输入并发起一次权威 GET。
6. POST 4xx：显示确定失败，不发起权威 GET。
7. GET 回执、Provider、模型、Base URL 和凭据状态均匹配：显示“已核对并生效”。
8. GET 返回旧回执、错回执或公开投影不匹配：不得用旧 `configured=true` 冒充本次提交，显示失败。
9. 首次 GET 失败：保持“待核对”，页面内仅保留 request ID 和公开目标字段。
10. 点击“刷新状态”：继续相同 request ID 的 GET，匹配才生效、不匹配失败、再次读取失败则继续待核对；全过程 POST 总数为 1。
11. 手动对账期间：刷新按钮 `disabled=true` 且 `aria-busy=true`；完成后恢复。
12. 对账期间存在识图、生图和平台凭据草稿：不触发整页加载、放弃草稿确认或图片能力刷新。
13. Provider/Agent 改写或删除当前主模型密钥：旧回执原子失效；同值、无关 Provider、仅修复重复行且实际生效值不变时保留回执。
14. API 公开响应与页面待核对状态：不包含密钥或密钥摘要。

## 空 / 加载 / 错误 / 成功 / 禁用状态

- 空状态：缺少 Provider、模型或可用凭据时显示“未配置”。
- 加载状态：保存中与待核对分别提供明确进度文案。
- 错误状态：确定请求错误、权威回执或公开投影不匹配时显示“保存失败”。
- 成功状态：权威状态匹配且无待刷新时显示“已生效”。
- 刷新状态：配置已提交但运行时待刷新时显示“刷新中”。
- 禁用状态：保存和手动对账期间禁用对应按钮并暴露忙碌语义。
- 破坏性状态：无；对账为只读 GET，不覆盖其它配置草稿。

## 剩余风险与边界

- 页面 pending 只承诺在同一页面生命周期内保留；整页重载后只展示新的权威状态，不再声称能证明旧请求 ID。
- 共享修订失效覆盖项目现有正式凭据写入函数；绕开这些函数直接手工改写 `.env` 不属于该原子合同。
- 自动化使用受控 API 与 DOM/Node 夹具，不能证明真实浏览器/Electron 的焦点、Toast 时序、网络层异常形态和渲染效果。
- 当前分支未合并正式 `main`，未重新制包，也未在麒麟安装态复验模型设置与二次启动。

## 后续建议

2. 在支持 setgid 的 Linux 测试环境重跑完整 Agent 凭据事务测试，关闭当前 8 项环境性缺口。
