# 桌面安全模式与扩展能力

正式安装通过开始使用检查要求：当前运行模式为 restricted、基础策略为企业安全或本机调试，且没有待重启生效的安全配置。两种基础策略均为有效选择，不强制使用企业安全。本机调试保留终端和代码执行风险说明，但不因此标记为“需要处理”；未知策略、状态读取失败和待重启配置仍需处理。此检查不改变任何实际工具权限。

## 用户操作

在「设置 → 系统 → 安全模式」选择基础策略，按需勾选「脚本任务」「委派」，再点击「保存安全设置」。新启用扩展时必须确认风险；取消不写入。保存后关闭并重新打开应用，再检查当前生效能力。

- 企业安全不自动开放 Terminal 或代码执行；启用扩展不改变这一点。
- 脚本任务允许执行应用脚本目录内的定时脚本，以当前用户权限运行，不逐次审批；只使用可信脚本。现有路径和符号链接边界保持。
- 委派允许创建子任务，可能增加模型调用和费用；保留工具继承、深度、数量与暂停限制，不自动启用子任务危险命令审批豁免。
- 两项扩展缺省关闭，切换基础策略保留已经保存的扩展选择。关闭脚本能力并重启后，已有任务不删除，但后续脚本执行被阻止。
- 开关显示编辑/保存选择；下方能力列表显示当前运行值。两者在等待重启期间可能不同，这是预期行为。
- 非桌面与完全开放运行态只读，不通过此接口修改。

## 接口兼容

`POST /api/security/profile` 接受 `profile`（strict / local_controlled）和可选 `capabilities` 对象。能力只接受 `unapproved_skill_scripts`、`delegate_task` 两个严格布尔值，不接受任意环境变量、未知字段或 null 对象。

省略能力或其中的字段时，原子写入只更新请求指定字段，保留磁盘上已有选择，不能用当前进程旧值覆盖待生效设置。缺省关闭由启动链保证。保存不修改当前进程环境。

`GET /api/security/status` 保留原生效状态字段，新增 `configured: {profile, capabilities}` 表示已保存选择；`restart_required` 比较基础策略和两项能力，兼容保留 `pending_profile`。保存响应中的 `status` 同样区分生效与保存状态。

## 验收边界

以配置保存、启动规范化、Agent 权限门禁、浏览器交互分层验证。源码测试不能证明麒麟新安装包已经更新；制包与目标机验收单独授权。
